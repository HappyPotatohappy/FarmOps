# 온도 변화와 실제 앙상블 재학습 실습

**BeeOPS_최종본 · 2026-10-01**

이 실습은 고정 합성 관측을 저장하고 실제 LSTM·앙상블 결합 비율을 학습하여 모든 벌통의 공통 모델에 적용하는 과정을 보여 준다. **SYNTHETIC 합성 자료**이며 실제 양봉장의 온도 영향이나 예측 성능을 입증하는 자료는 아니다.

## 1. 실행 준비

저장소를 clone하거나 GitHub ZIP을 내려받은 뒤 프로젝트 폴더에서 다음 명령으로 실행한다. 자체 학습 LSTM·scaler·결합 비율은 저장소에 포함되고, 큰 TiRex 체크포인트는 준비·빌드 단계에서 고정된 공식 배포본을 받아 SHA-256을 검증한다. Git LFS는 필요하지 않다. 첫 준비에는 네트워크가 필요하며 자세한 조건은 [README](../README.md)를 따른다.

```bash
docker compose up --build
```

대시보드 주소는 **http://localhost:8012**다. macOS에서 Docker 없이 직접 실행할 경우에는 같은 폴더에서 다음 명령을 사용한다.

```bash
sh setup.sh
sh start.sh
```

처음 시작할 때 기본 공개 사례는 브라질 Apis 2, Vecauce 3, 브라질 무침벌 1의 세 벌통이다. 고온 실습 저장 후 `TEMP-DRIFT-PRACTICE`가 추가된다. 이전 개발 서버의 원장은 이 폴더의 초기 상태가 아니며, 이후 관측과 학습 결과는 독립 저장소에 보존된다.

[CSV 묶음 다운로드](http://localhost:8012/data/simulations/temperature-drift.zip) · [로컬 ZIP](../data/simulations/temperature_practice.zip) · [생성 설정·파일 해시](../data/simulations/temperature_practice/manifest.json)

## 2. 가장 짧은 첫 실행

1. **데이터 → 온도 변화 실습**에서 고온 파일 `02_heatwave.csv`를 미리보기로 연다.
2. 신규·중복·충돌 행 수와 대상 `TEMP-DRIFT-PRACTICE`를 확인한다. 기본 고온 미리보기는 **정상 기준 336행 + 고온 168행, 총 504행**을 함께 확인하므로 기준 파일을 먼저 저장하지 않아도 된다.
3. **저장하고 재학습**을 누른다. 서버가 저장 작업을 접수하면 해당 벌통이 즉시 선택되고 대시보드로 이동한다.
4. 상단에서 관측 저장·재학습 준비, 실제 대기·학습·등록·적용 상태를 확인한다. 준비 중에는 학습이 시작됐다고 표시하지 않는다.
5. 완료 결과와 새 모델 버전·run ID를 확인한다. **빠르게 끝나도 결과는 확인 버튼을 누를 때까지 남는다.** 화면 이동·새로고침 후에도 미확인 실습 결과를 복원한다.
6. 확인을 누르면 알림을 닫는다. 이후 같은 과거 결과를 새 완료 알림으로 다시 표시하지 않는다.

실제 회차는 서버가 완료한 epoch 수다. 8/8회 이후에도 결합 비율 학습·최종 평가·등록이 진행 중이면 완료가 아니다. 모델 화면과 대시보드의 예측은 실제로 적용된 공통 번들을 사용한다. 고온 실습 접수 뒤 사용자가 직접 다른 벌통을 골랐다면, 늦게 도착한 완료 응답이 다시 TEMP 벌통으로 강제 전환하지 않는다.

## 3. 다시 실행할 때의 규칙

| 사용자의 행동 | 관측 원장 | 재학습 처리 |
|---|---|---|
| 처음 고온 미리보기 생성 후 저장 | 없는 기준·고온 행을 검증해 추가 | 실제 앙상블 학습 요청 |
| 완료 후 새 고온 미리보기 생성 후 저장 | 같은 504행은 중복으로 보존 | 새 명시적 요청으로 실제 재학습 |
| 같은 미리보기의 저장 요청 재시도 | 중복으로 삽입하지 않음 | 같은 가져오기 작업 반환, 이중 학습 방지 |
| 같은 실습이 이미 대기·학습 중인 동안 새 저장 요청 | 중복으로 삽입하지 않음 | 이미 실행 중인 실제 작업을 함께 추적 |
| 일반 CSV 업로드로 같은 자료 재업로드 | 같은 관측은 보존 | 명시적 실습 재실행 권한을 부여하지 않음 |

새 실습은 현재 적용 모델에서 이어 학습한다. 따라서 학습 전후 버전, 결합 비율, MAE, 소요 시간은 매번 같다고 보장하지 않는다. 새로 저장된 행이 0개여도 **새 실습 요청에 따른 실제 모델 학습**은 진행할 수 있다. 데이터 중복 방지와 사용자가 요청한 재학습 반복은 서로 다른 계약이다.

고온만 먼저 저장한 정확한 기본 실습 원장이 있어도 누락된 기준 관측을 복구할 수 있다. 서버는 기본 파일 해시와 기존 관측값을 확인하고 저장 직전에 다시 검증한다. 사용자가 바꾼 값·다른 후속 자료가 섞였다면 원장을 덮어쓰지 않고 오류로 안내한다. 단순히 파일 이름을 `02_heatwave.csv`로 바꾼 일반 업로드에는 이 예외를 적용하지 않는다.

## 4. 자료와 정상 대조군

| 파일 | 시간 관측 수 | 역할 |
|---|---:|---|
| `01_baseline.csv` | 336 | 약 24°C의 일주기 정상 기준 |
| `02_heatwave.csv` | 168 | 처음 12시간에 약 +8°C까지 상승한 뒤 유지 |
| `03_followup.csv` | 72 | 고온 상태가 유지되는 후속 관측 |
| `control/01_baseline.csv` | 336 | 별도 `TEMP-CONTROL-PRACTICE`의 정상 기준 |
| `control/02_normal.csv` | 168 | 온도 상승 처리를 넣지 않은 정상 대조군 |

표의 168행은 고온 파일 자체의 크기다. 화면의 기본 고온 미리보기는 기준 파일을 합쳐 504행을 사용한다. 기준 파일을 따로 먼저 저장해도 괜찮으며 고온 단계에서 이미 존재하는 기준 행은 중복 처리한다.

후속 파일은 고온 재학습 결과를 확인한 뒤 저장한다. 대조군은 ZIP의 두 control 파일을 일반 CSV 업로드로 차례로 저장한다. 관측 저장만으로 모든 예측·평가 쌍이 만들어졌다고 설명하지 않는다. 과거 비교 차트는 현재 모델로 다시 계산한 값이고, 당시 미리 저장한 미래 예측의 운영 성능과 다르다.

CSV는 `timestamp,hive_id,weight_kg,temperature_c,event` 다섯 열이다. 단계 간 시각은 정확히 한 시간씩 이어지고 event는 모두 `normal`이다. 난수 seed는 `20261001`이다. 합성 무게는 일주기와 온도 부하를 사용해 만들었으며 모델 정확도를 데이터에 넣지 않았다.

## 5. 일반 온도 감시와 명시적 실습의 차이

일반 온도 감시는 최초 연속 정상 168시간의 평균·표준편차를 저장한다. 기준 종료 이후 새로운 정상 관측이 24시간 모이면 최신 24시간과 비교한다.

```text
shift = abs(최근 24시간 평균 - 저장된 기준 평균)
shift >= 4°C
shift / max(기준 표준편차, 1°C) >= 1.5
```

두 조건을 모두 만족해야 자동 요청한다. 신규 관측 23시간은 기다리고, 사건·시간 공백 뒤에는 연속 구간을 다시 센다. 동일 관측·기준의 자동 요청은 반복 실행하지 않는다. 이 수치는 입력 분포 변화의 동작을 보여 주는 공학적 기준이며 벌통 건강이나 질병 판정 기준이 아니다.

반면 **기본 고온 저장 버튼은 사용자가 요청한 실습 실행**이다. 고정 정상 기준과 고온 자료를 다시 사용하도록 명시적으로 허용한다. 이미 갱신된 운영 기준을 매번 초기 기준으로 되돌리지 않으며, 후속 관측으로 더 나중 기준이 저장되어 있다면 실습 완료 후에도 보존한다.

## 6. 실제 학습과 평가의 의미

공통 레지스트리는 `BeeOPS_Horizon_Weight`다. 현재 부모 모델에서 실제 TensorFlow LSTM을 **8회** 추가 학습하고, 실제 TiRex-2 예측과 LSTM 예측으로 결합 비율을 다시 선택한다. TiRex-2 체크포인트와 부모 scaler는 유지한다. 두 모델의 비중은 각각 5~95%의 양수이며 선택 비율이 이전과 같을 수도 있다.

고정 고온 실습의 목표 구간은 **LSTM 학습 120개 창 → 결합 비율 보정 24개 시점 → 최종 평가 24개 시점**이다. 학습 목표는 보정 구간을 넘지 않도록 제한하고 결합 비율은 보정 정답으로만 선택한다. 최종 평가 정답은 해당 실행의 비율 선택에 쓰지 않는다.

그러나 반복 실습은 같은 합성 자료를 다시 사용한다. 이전 모델이 이미 이 자료의 영향을 받았을 수 있으므로 결과는 `data_reused=true`, `independent_future_evaluation=false`로 기록한다. **실제 학습·등록을 보여 주는 설명용 1시간 평가이며 독립적인 새 미래 성능이나 7일 정확도 증거가 아니다.**

모델을 저장하고 다시 로드하여 기술적으로 유효한지 확인한 뒤 MLflow에 등록하고 공통 적용 포인터를 갱신한다. 임의의 MAE 개선 목표로 등록을 차단하지 않는다. 자료 부족·학습 실패·등록 오류는 실제 상태로 남긴다. 적용 후 부가 기록 저장만 실패하면 이미 적용된 모델을 실패 전 모델처럼 표시하지 않는다.

일반 **앙상블 재학습** 버튼도 같은 학습 엔진을 사용하지만, 명시적 고온 재실행과 달리 입력 문맥 168시간과 아직 소비하지 않은 정상 목표값 24개 이상이 필요하다. 같은 스냅샷을 다시 요청하면 기존 평가 작업을 반환할 수 있다.
