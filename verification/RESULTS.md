# 최종본 검증 기록

검증일: 2026-10-01. 대상은 이 독립 폴더의 소스·초기 모델 v9·제공 CSV입니다. 기존 실행 서비스와 다른 포트·저장 볼륨을 사용했습니다. 테스트에서 생성한 v10·v11은 검증용 볼륨의 기록이며, 팀원이 처음 실행할 때는 v9와 공개 관측 사례 3개로 시작합니다.

## Windows·Mac 공통 실행 환경

`python:3.11.15-slim-bookworm` 기반의 Linux ARM64와 AMD64 이미지를 실제 빌드했습니다. 두 Python 환경의 의존성 검사가 통과했고, 이미지 내부에서 공식 체크포인트를 새로 내려받아 크기·SHA-256을 확인했습니다. 호스트의 모델 파일은 Docker 빌드에 넣지 않아 GitHub에서 체크포인트 없이 내려받는 경로를 검증했습니다.

| 환경 | 실제 실행 확인 |
|---|---|
| Linux ARM64 / Apple Silicon Docker | 세 공개 벌통 각각 168시간 미래 예측·과거 예측 생성, 같은 공통 모델 ID 확인, 문서·PDF·ZIP 다운로드 |
| Linux AMD64 / Apple Silicon Docker 에뮬레이션 | 1시간·168시간 예측, 채밀 기간 계산, 고온 관측 504행 저장, LSTM 8회·결합 가중치 학습, v9→v10 적용 및 기존 벌통 추론 |

Windows 실기기 자체에서는 실행하지 않았습니다. Windows 팀원은 WSL 2 기반 Docker Desktop에서 검증한 동일 Linux AMD64 빌드 경로를 사용합니다. 네트워크 정책, 디스크와 Docker 설치 문제까지 모든 팀원의 기기에서 확인한 것은 아닙니다. 외부 인터넷은 처음 라이브러리와 모델을 받을 때 필요합니다.

구체적인 모델 ID와 예측값은 [ARM64 예측](arm64_readonly.json), [AMD64 실행](amd64_execution.json)에 있습니다. 이 검사는 설치·추론·학습의 동작을 확인하며 예측의 현장 정확도나 사업 효과를 입증하지 않습니다.

## 반복 고온 실습과 알림

빈 ARM64 실행 저장소에서 Chrome으로 다음을 확인했습니다.

1. 데이터의 고온 기간 파일을 불러와 저장하자 `TEMP-DRIFT-PRACTICE` 선택과 대시보드 이동이 바로 이루어졌습니다.
2. 저장·준비 상태 다음 실제 LSTM 8회 학습, 결합 비율 계산, 등록·적용 단계가 표시됐습니다.
3. v9→v10 완료 알림은 새로고침 뒤에도 남았고 `확인`으로 닫혔습니다.
4. 같은 고온 파일을 다시 불러와 저장하자 두 번째 실제 작업이 실행됐습니다. 504행은 중복 저장하지 않고 v10→v11로 학습했으며 새 완료 알림도 표시됐습니다.
5. 두 작업 모두 LSTM 파라미터의 해시가 달라졌고 TiRex-2 본체 해시는 동일했습니다. 7개 처리 단계 모두 완료했습니다.
6. 컨테이너를 재시작해 v11, 작업 2개, 관측 504행 보존과 새 168시간 추론을 확인했습니다.

작업 ID와 전후 해시는 [반복 재학습·재시작 검사](arm64_retraining.json)에 기록했습니다. 이 과정은 고정 합성 자료의 실습 반복이며 독립 미래 성능 평가가 아닙니다.

## 다시 확인하기

저장소 루트의 [README](../README.md)에 설치·종료·테스트 명령을 정리했습니다. `scripts/smoke_demo.py`는 기본적으로 공개 사례 예측과 문서 접근을 점검합니다. `--train --repeat 2`를 붙이면 현재 실행 저장소에 고온 자료를 저장하고 실제 재학습을 두 번 실행합니다.

이 문서는 게시 전 로컬 검증 기록입니다. 제공 workflow와 같은 가벼운 검사를 별도 소스 복사본에서 통과했습니다. 게시된 커밋의 GitHub 검사 결과는 저장소 Actions에서 확인합니다.

실제 Git ZIP에서 다시 빌드한 게시 전 결과와 패키징 보완 내용은 [GitHub 다운로드 재현 검증](GITHUB_DOWNLOAD.md)에 있습니다.
