BeeOPS 최종본 · 6분 시연 가이드

팀원 재현용 · 2026-10-01

현재 제품은 공통 TiRex-2 + LSTM으로 향후 168시간 무게를 예측하고, 관측 저장·온도 감시·실제 앙상블 재학습을 연결한다. 예전 BEE-DEMO의 버전별 품질 게이트나 24시간 입력 LSTM은 이번 발표의 주 경로가 아니다.

발표 전 준비

저장소를 clone하거나 GitHub ZIP을 내려받은 뒤 README의 환경 확인을 따른다. Git LFS는 필요하지 않으며 큰 TiRex 체크포인트는 첫 준비·빌드에서 고정된 공식 배포본을 다운로드하고 해시를 검증한다. 자체 학습 LSTM과 결합 비율은 저장소에 포함된다. 프로젝트 폴더에서 다음 명령으로 실행한다.

bashdocker compose up --build

주소는 http://localhost:8012다. macOS 직접 실행은 sh setup.sh 후 sh start.sh를 사용한다. 초기 데이터는 브라질 Apis 2·Vecauce 3·브라질 무침벌 1의 세 공개 사례다. 최초 포함 모델은 번들 9지만 이후 학습하면 바뀌므로 발표 직전에 모델 화면의 활성 버전과 가중치를 확인한다.

모델 최초 로드·실제 학습 소요 시간은 장비에 따라 달라진다. 여섯 분은 설명 순서이며 학습 완료 시간을 보장하는 수치가 아니다. 빠르게 학습이 끝나도 고온 실습 완료 결과는 확인 버튼 전까지 유지된다.

0:00~0:45 · 해결하려는 문제

“BeeOPS는 벌통의 무게와 외기온 기록을 모아 최근 변화와 앞으로 일주일의 예상 흐름을 확인하는 서비스입니다. 채밀 날짜를 자동 확정하기보다 현장 점검할 후보 기간과 판단 근거를 제공합니다.”

기획서의 사용자별 역할과 HAIC 도메인 매핑을 짚는다. 벌통 무게는 벌꿀 생산량과 같지 않고, 급격한 하락만으로 질병·분봉·채밀을 확정하지 않는다.

0:45~2:00 · 실제 관측과 같은 모델의 다른 예측

  1. 브라질 Apis 2를 선택해 관측 곡선, 현재 모델의 과거 예측 비교, 미래 7일 경로를 보여 준다.
  2. Vecauce 3와 브라질 무침벌 1로 바꾸어 입력 관측에 따라 예측이 달라지는 것을 확인한다.
  3. 모델 선택·예측 길이 선택 없이 현재 공통 모델이 적용되고, 추천은 그 예측 경로에서 계산됨을 설명한다.

“각 벌통의 최근 연속 168시간을 같은 LSTM과 TiRex-2에 넣습니다. 미래 168개 시간값과 채밀 후보 기간은 실제 예측 결과에서 계산합니다. 과거 비교는 현재 모델로 다시 예측한 값이므로 당시 미리 저장된 운영 성능과는 다릅니다.”

2:00~3:00 · 고온 실습을 저장하고 바로 대시보드로

  1. 데이터 화면의 온도 변화 실습에서 고온 02_heatwave.csv를 미리보기로 연다.
  2. 미리보기의 총 504행은 정상 기준 336행과 고온 168행이 합쳐진 것임을 설명한다. 기준 파일을 먼저 저장하지 않아도 된다.
  3. 신규·중복·충돌 수를 확인하고 저장하고 재학습을 누른다.
  4. TEMP-DRIFT-PRACTICE가 즉시 선택되고 대시보드의 준비·대기·학습 상태가 보이는지 확인한다.

“동일 관측은 덮어쓰거나 두 번 저장하지 않습니다. 여기의 저장 버튼은 고정 합성 자료로 실제 재학습을 실행하라는 요청이기도 합니다. 아직 학습 작업이 생기지 않은 동안에는 준비 상태를 보여 줍니다.”

3:00~4:20 · 실제 재학습과 완료 결과

실제 완료 epoch 수와 단계 표시를 보여 준다. LSTM이 8/8회 끝나도 결합 비율 보정·최종 평가·등록이 남으면 작업 완료가 아니다. 화면을 이동하거나 새로고침해도 같은 작업 ID를 따라가는지 확인한다.

“LSTM 파라미터를 실제로 학습하고, 별도의 시간 구간에서 두 예측의 결합 비율도 다시 선택합니다. TiRex-2 체크포인트는 고정합니다. 이후 시점의 평가와 모델 재로드를 거쳐 등록한 번들을 모든 벌통에 적용합니다.”

완료 시 새 번들·run ID·이전과 새 비율을 확인한다. 결과는 확인 버튼을 누를 때까지 남는다. 빠르게 끝났다면 이 완료 결과와 실제 저장된 학습 기록을 설명하며, 재학습 중인 화면을 꾸며 내거나 강제로 지연시키지 않는다.

4:20~5:10 · 반복 실행과 실패를 구분

  1. 완료 결과를 확인한 뒤 새 고온 미리보기를 만들고 다시 저장한다.
  2. 신규 0행·중복 504행이어도 새 명시적 요청에 따라 실제 모델 학습이 실행될 수 있음을 확인한다.
  3. 같은 미리보기의 저장 요청을 재시도하면 같은 작업을 반환하고, 이미 같은 실습이 실행 중이면 그 실제 작업에 연결됨을 설명한다.
  4. 새 작업의 실제 상태와 결과를 확인한다. 실패·중단을 성공으로 설명하지 않는다.

일반 온도 감시와 일반 수동 재학습은 같은 관측을 무조건 다시 학습하지 않는다. 고정 자료를 반복 학습하는 것은 이 명시적 합성 실습의 정책이다.

5:10~6:00 · 평가 의미와 한계

“입력 시점 뒤의 정답을 예측 입력에 넣지 않고, 한 번의 학습 안에서도 LSTM 학습·결합 비율 보정·최종 평가 목표를 나눕니다. 다만 반복 실습은 이미 사용한 합성 자료를 재사용하므로 독립적인 새 미래 시험이 아닙니다. 1시간 MAE를 7일 정확도나 양봉 생산량 개선으로 확대하지 않습니다.”

공개 사례는 UFC Apiary와 Vecauce의 CC BY 4.0 자료이며, 실제 현장 센서 자동 연동이나 상용 운영은 후속 과제임을 설명한다. 프로젝트의 성과는 실제 관측·예측·학습·등록·공통 적용과 오류 추적이 연결되었다는 점이다.
